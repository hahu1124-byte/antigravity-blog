🔥 7月の3大トピック

📡 ① MCP 2026-07-28仕様リリース候補 — プロトコル最大の改訂

発表以来最大級の見直しとなるRCが公開されました。Streamable HTTPからセッション概念を撤廃（Mcp-Session-Idヘッダー廃止）し、通常のHTTPインフラだけでスケールする「ステートレスコア」へ移行。初期化ハンドシェイクも撤廃され、サーバーがサンドボックス化されたHTML UIを配信できる「MCP Apps」が新設されました。正式仕様は7月28日公開です。

🚨 ② 「Friendly Fire」攻撃の公表 — 自律承認モードの死角

AI Now Instituteが公表した攻撃手法「Friendly Fire」は、Claude CodeやOpenAI Codexが自律モードで自分自身のコマンドを承認してしまう設計を悪用するもの。本来「信頼できないコードを検査する」役目のエージェント自身が侵入経路になり得ることが実証されました。同時期にClaude Code GitHub Actionのサプライチェーン汚染、50万以上のOSSデプロイに影響する「GuardFall」脆弱性も発覚し、7月は業界全体で権限設計の見直しが進んだ月となりました。

💰 ③ Cursor、Continueを買収しM&A加速

CursorがOSSコーディングアシスタント「Continue」（34K Stars）を買収し製品終了、コードベースはコミュニティへ移管。CursorはARR30億ドル超・評価額は293億ドルから600億ドルへ急伸しました。同時にAutomations・iOS公開ベータ・Slack連携強化を投入し、統合と淘汰のフェーズに入っています。

🔑 第11回の4断層

  • 信頼断層: 「エージェントの自律承認は信用できるか」が初めて業界全体の議題に。Friendly Fireが突きつけた問いは根本的
  • プロトコル断層: MCPのステートレス化により、旧セッション前提の実装は大規模な書き換えが必要に
  • 資本断層: 中堅OSSプロジェクトの生存戦略が「財団移管」（Goose）と「大手買収」（Continue）の二極化へ
  • 検証断層: 「エージェントを作れる」から「エージェントの弱点を見抜ける」へ、開発者に求められるスキルの重心が移動

🎯 第11回の結論

  • 当面の推奨体制: 自律承認フローの権限設計を必ず点検した上でClaude Code / Devin Security Swarm等のセキュリティ対応済みツールを使う。無審査の自律承認は避ける
  • Friendly Fireの教訓: 「エージェントが自分のコマンドを承認する」設計は便利さとリスクが表裏一体。人間のレビューを外す判断は慎重に
  • MCP移行の実務: 自作MCPサーバーがある場合、セッション・ハンドシェイク撤廃を前提に10週間の移行猶予内での対応計画を立てる
  • OpenCodeの意味: セキュリティ危機の中でOSS・ローカル完結設計の価値がさらに上昇。182K Stars・8M開発者という数字はその裏付け
